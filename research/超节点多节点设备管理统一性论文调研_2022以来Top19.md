### 7. HyperOffload: Graph-Driven Hierarchical Memory Management for LLMs on SuperNode Architectures

### 13. A Programming Model for Disaggregated Memory over CXL

### 14. Pond: CXL-Based Memory Pooling Systems for Cloud Platforms

### 17. Understanding the Synchronization Tax in GPU Scale-Up Domains

- **arXiv**: [2605.19481](https://arxiv.org/abs/2605.19481)（2026-05）| 引用数：0（OpenAlex）

### 19. DWDP: Distributed Weight Data Parallelism for High-Performance LLM Inference on NVL72
- **arXiv**: [2604.01621](https://arxiv.org/abs/2604.01621)（2026-04）| 引用数：0（OpenAlex）

- **课题相关性**: 直接利用 NVL72 对等互连与统一地址空间的"单一节点"能力：权重分布在对等 GPU 上可按需直接访问，无需跨层同步。它展示了单一节点抽象如何释放数据并行潜力--这是"把多节点当单节点"在高带宽互连上的经典收益场景，也是 UBEP 所解决同步问题的同题反面。

## 前沿动态与研究空白

**近期趋势（2026 年论文标注 `[新]`）**：本课题最显著的前沿是**超节点软件栈的整体爆发**--2026 年上半年密集出现了围绕"统一内存语义 + 高带宽 fabric 如何落成软件"的工作：UBEP、StrataCL 重构通信库，HyperParallel、HyperOffload 重构框架与内存管理（均为 `[新]`）。这说明硬件（CloudMatrix384、NVL72 等）已经先行，学术前沿正转向"单一节点抽象"的软件实现层。

**值得注意的新信号**：Synchronization Tax（[17]）`[新]` 首次量化了"把多节点当单一节点"后隐式同步开销随域规模膨胀的张力，这可能是超节点规模化的下一个硬瓶颈；Completion-Path Credits `[新]` 则从接收端多资源流控角度回应 scale-up fabric 的资源竞争。

**研究空白**：
1. **UB 编程模型的形式化**：CloudMatrix/UBEP/StrataCL 提供了工程实现，但"统一内存语义如何保证一致性与崩溃安全"的编程模型研究（如 CXL 侧的 [13]）在 UB 体系下仍属空白；
2. **跨厂商统一设备抽象层**：NVL72（NVLink）、CloudMatrix（UB）、CXL 池各自为政，缺乏统一的上层抽象标准，本文未见直接对此的论文；
3. **中文核心文献的系统研究**：本次 CDP 不可用导致知网（CSCD/北大核心）未覆盖，中文侧是否存在对灵衢/UB 的独立学术分析（不同于华为英文技术报告）尚待补充；
4. **同步税的软件缓解**：Sync Tax 已量化问题，但针对性的调度/编译缓解方案仍少。
