# 超节点（SuperPod）论文检索工作流

本目录用于特定课题范围的论文检索与调研：根据用户给出的课题，调用 academic-search skill 在多个数据库和平台检索、分析论文，最终在 `research/` 目录输出完整、可回溯的检索报告并归纳总结。

**所有输出（报告、摘要、对话）一律使用中文**，论文标题、术语保留英文原文。

---

## 一、课题背景（固定上下文）

**当前课题**：AI 基础设施超节点（supernode / superpod）硬件体系架构，聚焦**节点设备的管理与互联互通**方向。

**核心研究问题**：如何做到通过超节点实现对多节点设备管理的统一性--在软件视角下，将多个节点上的设备看作单一节点进行资源管理和通信，比如通过如灵衢总线（UB，UnifiedBus）的统一内存语义和高带宽通信等方法。

**优先级规则**：凡涉及**灵衢总线（UnifiedBus / UB）或华为超节点体系（CloudMatrix、昇腾 SuperPOD 等）**的论文，一律作为**最高优先级**摘录：自动进入核心论文列表（无需等待用户确认）、置于报告首组、优先深拉全文，无论引用数高低、发表时间新旧。

**课题关键词矩阵**（检索式构造的起点，需持续补充）：

| 概念维度 | 英文检索词 | 中文检索词 |
|---------|-----------|-----------|
| 超节点本体 | supernode, superpod, scale-up domain, rack-scale, pod-scale | 超节点, 智算单元, 规模扩展域 |
| 灵衢/华为系统（最高优先级） | UnifiedBus, UB interconnect, CloudMatrix, Ascend SuperPOD, unified memory semantics, high-bandwidth bus | 灵衢, 灵衢总线, 昇腾超节点, CloudMatrix, 统一内存语义 |
| 设备管理统一性 | unified device abstraction, resource disaggregation, composable infrastructure, single-node abstraction | 资源解耦, 可组合基础设施, 统一资源管理 |
| 互联互通 | scale-up fabric, interconnect topology, CXL, collective communication | 互连网络, 总线互联, 集合通信 |
| 软硬协同 | communication library, parallelism strategy, distributed runtime | 通信库, 并行策略, 分布式运行时 |

用户也可能提出**新课题**。此时课题背景以用户当次输入为准，但工作流不变。

**默认检索参数**（用户当次指定时覆盖）：

- 时间范围：2022-01 至今
- 目标数量：核心论文 Top 15-20 篇 + 备选清单
- 语言：**中英文并重**--英文文献（arXiv / 国际平台）与中文核心文献（知网 CSCD / 北大核心）两类均须覆盖，缺任一类时在报告"局限"中说明原因
- 学科路由：计算机系统/体系结构 -> 读取 skill 的 `references/disciplines/computer-science.md`

## 二、工具与能力边界

核心工具是 **academic-search skill**（检索、元数据提取、引用数、OA PDF 判定、BibTeX）。使用前先明确边界，**不要承诺 skill 做不到的事**：

### 平台分层

| 层级 | 平台 | 访问方式 | 说明 |
|------|------|---------|------|
| 核心（API，无需浏览器） | arXiv、Semantic Scholar、OpenAlex、Crossref、Unpaywall | REST API | 优先使用，速度快 |
| 核心（CDP，需浏览器） | Google Scholar、CNKI 知网 | CDP 直连用户 Chrome | 无 API；见下方前置检查。**中英文并重策略下，知网为核心必查平台** |
| 尽力而为 | ACM DL、IEEE Xplore | WebFetch / Jina | 访问常受限，失败时降级并记录 |
| **不在支持范围** | Scopus、Web of Science | - | 商业数据库无公开访问，**不得列入检索承诺**；未覆盖时在报告"局限"中声明 |

### 能力红线

- **引用数**：可从 S2 / OpenAlex / Google Scholar 获取（各平台数值不一致属正常，注明来源即可）；中文文献被引数以知网为准。
- **影响因子（IF）**：各 API 均不提供，**不要承诺获取**。替代方案：venue 等级标注--CS 会议/期刊用 CCF 分级（skill 的 `references/venue-rankings.md`）。
- **知网来源库**：本课题为计算机方向，中文核心文献选 **CSCD / 北大核心**，**不要勾选 CSSCI**（社科索引，会筛掉几乎所有相关文献）。
- **PDF 下载**：只下载合法开放获取（OA）论文，走 skill 的 manifest 流程。**禁止** Sci-Hub、LibGen、付费墙绕过等任何渠道。
- **分工**：检索、元数据、BibTeX 数据 -> 调用 academic-search skill；相关性分析、综述撰写、引用格式转换（GB/T 7714 等）-> Agent 基于检索到的元数据自行完成，skill 不负责。

## 三、工作流

按步骤执行。**步骤 2 -> 3 之间和下载前各有一个用户确认点，不要跳过**（灵衢/华为超节点论文按优先级规则自动进入核心列表，不受确认点约束）。

### 步骤 0：前置检查

```bash
bash ~/.claude/skills/academic-search/scripts/check-deps.sh
```

- 仅用 API 平台（arXiv/S2/OpenAlex）时，Node.js 与 curl 就绪即可开始。
- 需要 Google Scholar 或 CNKI 时，确认 Chrome remote-debugging 已开启（`chrome://inspect/#remote-debugging` 勾选 Allow remote debugging）。**中英文并重策略下应尽早确认 CDP 可用性**，否则知网检索无法执行。
- **降级规则**：CDP 不可用时跳过 Google Scholar / CNKI 检索，继续执行其余步骤，并在最终报告"检索方法说明"中**显式声明覆盖缺口**（参照已有报告的"局限"写法），不得静默缺失。
- **限流处理**：S2 无 API Key 时极易 429；触发后切换 OpenAlex 补充引用数（已有报告即采用此降级路径），不要对同一请求反复重试。

### 步骤 1：课题解析与检索式构造

**不要拿到课题直接搜**。先完成：

1. 从用户课题中提炼核心概念维度（参考上方关键词矩阵）；
2. 构造 2-3 组互补的**中英文**检索式：同义词替换（supernode/superpod）、子概念拆分（设备管理统一性 -> unified device abstraction / resource disaggregation / composable infrastructure）、缩写与全称并用；中文检索式独立构造（如"灵衢总线"、"超节点 统一内存"），不是英文检索式的直译；
3. 将检索式列表呈给用户确认后再执行（用户已在当次输入中给出明确关键词时可跳过确认）。

### 步骤 2：第一遍检索--轻量摘要表（获取层）

**目标：广覆盖、轻量，不拉完整摘要。**

1. **并行分治**：多平台并发时使用子 Agent，prompt 写目标（"获取 XX 的引用数"）不写手段，且必须写明"必须加载 academic-search skill 并遵循指引"；
2. 平台顺序：arXiv（英文主检索）-> 知网 CNKI（中文主检索，KNS8 高级检索，主题字段 SU，中文关键词 OR 连接，来源 CSCD/北大核心）-> Semantic Scholar / OpenAlex（引用数与元数据核对）-> ACM DL / IEEE（尽力而为）-> Google Scholar（CDP 就绪时）；
3. 每平台拉 20-30 条，输出轻量摘要表：**标题、年份、venue、引用数、是否有开放 PDF**；
4. **去重合并**：DOI -> arXiv ID -> 标题+年份模糊匹配（skill 的 `references/metadata-schema.md` 规则），合并为单一结果集；中英文结果分别列表，互不混排；
5. 知网操作前读取 skill 的 `references/site-patterns/cnki.net.md` 获取 DOM 选择器与陷阱（JS 渲染延迟、翻页限制、CAPTCHA 处理）。

**-> 确认点 1**：将轻量摘要表呈给用户，按"引用数 + venue 等级 + 与课题相关性"推荐核心论文 5-10 篇（灵衢/华为超节点论文已按优先级规则自动入选），由用户确认或调整。

### 步骤 3：第二遍深拉--完整元数据与 OA 判定（获取层）

**只对确认后的核心论文深拉，不对全量结果操作。**

1. 拉取完整元数据：摘要、作者全列表、venue、DOI、引用数、关键词，统一为 skill 的 metadata schema；
2. OA 状态判定：按 skill 的优先级链（arXiv 直链 -> S2 openAccessPdf -> OpenAlex -> Unpaywall），每篇记录 `full_text_status`；
3. 生成下载 manifest：`node scripts/oa-pdf-download.mjs --input <metadata.json> --manifest <manifest.json>`；
4. **-> 确认点 2**：manifest 呈给用户，确认后 `--download --out-dir` 下载开放 PDF；非 OA 论文不下载，在清单中说明原因（建议机构图书馆/邮件索取）。

### 步骤 4：分析与撰写（分析层，Agent 自行完成）

基于步骤 3 的元数据，**不要调用 skill 做"分析"**：

1. **课题相关性分析（每篇必写）**：每篇核心论文单列一条"课题相关性"，从**研究领域、切入角度、方法**三个维度深入分析其与核心研究问题的相关性--即与"多节点设备管理统一性 / 单一节点抽象 / 统一内存语义（如灵衢 UB）"的关联，明确回答"这篇论文对核心研究问题有什么直接支撑、借鉴或对照价值"；仅主题沾边而无实质关联的，如实写"相关性有限"并说明；
2. **主题分组归纳**：将论文按研究主题聚类（如：灵衢/华为超节点体系（首组）/ 真实系统部署一手资料 / 互连拓扑 / 光互连 / 软硬协同 / 趋势综述），这是"归纳总结"的落点；
3. **前沿动态**：基于检索结果总结该方向的学术前沿（近 6 个月论文标注 `[新]`）、研究空白与趋势判断；
4. **中文摘要**：每篇生成 2-3 句中文简介，便于快速浏览。

### 步骤 5：引用规范化（输出层）

1. **硬性约束：所有参考文献必须来自本次检索实际返回的元数据，禁止凭模型记忆生成任何条目**。每条引用可回溯到平台来源（arXiv ID / DOI / CNKI 链接）；
2. BibTeX 获取：arXiv 直链（`https://arxiv.org/bibtex/{arxiv_id}`）-> ACM DL 导出端点 -> S2 字段拼装；中文文献按 GB/T 7714 手工拼装（知网导出格式为基准）；
3. 报告正文引用格式以 **GB/T 7714**（中文文献必须）为主，英文文献可用 GB/T 7714 或 APA，全文保持一致；
4. 检查引用完整性：作者、年份、venue、DOI 缺一不可，格式统一。

## 五、执行原则

1. **先定义成功标准再动手**：明确本次要的是摘要表（第一遍）还是完整报告，数量、字段、时间范围，以此锚定何时停止；
2. **失败信号即方向**：同一方式重试 3 次无改善就换平台或换访问方式（skill 的失败信号表），不空转；
3. **诚实呈现**：没搜到的平台写进"局限"，拿不到的字段（如影响因子）明说，宁缺毋假；
4. **完成即止**：对照成功标准确认完成后停止，不为"更完整"而过度检索；
5. **工作目录约束**：始终以当前目录（`research/`）作为工作目录；所有临时文件、临时下载、各类临时目录统一在 `./tmp/` 下操作并按用途建子目录（如 `./tmp/download/`、`./tmp/superpod_search/`），**禁止写入系统 `/tmp` 或当前目录其他位置**。
